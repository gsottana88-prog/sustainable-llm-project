The project in one page

Can a shorter prompt make AI more sustainable?

LLMs process input tokens every time they answer. This project tests whether we can keep the useful context, discard the unnecessary context, and reduce total energy use without losing answer quality.

Core study: classical compressionStretch study: simulated QAOADifficulty: about 5–6/10 with OpenCode

1. The central idea

Compression is only useful if it saves more resources than it consumes.

📚

Long context

Many sentences enter the LLM, including details that may not help answer the question.

→
🎯

Relevant context

Select the most useful sentences, use fewer input tokens, and test whether the answer stays just as good.

Research questionCan context selection reduce total inference energy while maintaining answer quality compared with classical baselines?

2. Experiment flow

This is the practical workflow—from data to an evidence-based conclusion.

STEP 01 · INPUT

Question + passages

Use HotpotQA. Start with 20 questions; expand to 50–100 only if the pipeline is reliable.

→
STEP 02 · BASELINE

Full-context LLM

Run Qwen2.5-0.5B-Instruct with all context. Record answer, tokens, latency and energy.

→
STEP 03 · COMPRESS

Select sentences

Keep relevant sentences under a token budget. First use TF-IDF or greedy classical selection.

↓
OPTIONAL BRANCH

Exact search → simulated QAOA

For only 6–8 candidate sentences, compare an exact classical reference with QAOA running on a classical simulator. No quantum hardware or quantum-advantage claim.

STEP 04 · EVALUATE

Same questions, fair comparison

Measure answer quality, evidence recall, tokens, selector overhead, inference time and energy for each method.

↓
STEP 05 · CONCLUSION

Did we save energy without harming answers?

Compare the full-context baseline against compressed approaches, including the energy used to select and optimise context.

3. What counts as success?

A lower token count alone is not enough.

📉 Token reductionHow much shorter is the input?
🎯 Answer qualityDo exact match / F1 remain acceptable?
⚡ Total energyDoes inference energy saved exceed selection overhead?
⏱️ Total latencyDoes selection make the overall system slower?

Good result

Fewer tokens, similar answer quality, and lower total energy after including selection costs.

Important negative result

Compression saves tokens but loses evidence or consumes more energy than it saves. That is still a valid finding if measured honestly.
